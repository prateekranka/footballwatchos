# Football OS: Batched-Motion Default, Package Fixes Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Make batched Core Motion the only recording mode (no safe mode), prove date integrity end-to-end, and surface motion evidence in both apps.

**Architecture:** Watch app records via `HKLiveWorkoutBuilder` (heart rate, distance) plus `CMBatchedSensorManager` (accelerometer, device motion) into an append-only `.footysession` package. iPhone imports packages over WatchConnectivity into `FileSessionRepository` and renders charts. Changes touch the Watch capture controller, the shared package types/tests, and the iPhone detail views.

**Tech Stack:** Swift 6, SwiftUI, HealthKit, CoreMotion, CryptoKit, XCTest. Project generated by XcodeGen (`project.yml`). Build/test via `xcodebuild` (never FlowDeck).

## Proposed Approach

1. Delete the `MotionCaptureRuntimeMode` abstraction entirely. Batched Core Motion stays the default plan; existing hardware-degradation ladder (batched → foreground fallback → unavailable) remains because it reflects hardware truth, not policy.
2. Extend the shared reader/repository/detail pipeline so motion batches survive to the UI, with charts on iPhone.
3. Pin date fidelity with a cross-target round-trip test.
4. Show capture source prominently on the Watch recording screen.
5. Bump build number, run both suites, ship a device build via sqim.

## Risks and Tradeoffs

- **Init-signature change (Task 1)** breaks any other `MotionCaptureController(runtimeMode:)` callers — compiler will find them; only `WorkoutRecorder.swift:39` known today.
- **Motion frame volume**: a 70-minute match at ~50 Hz ≈ 210k accelerometer + 210k device-motion samples. Package frames are capped at 1 MiB (`maximumFrameBytes`); batching logic already emits ≤50-sample frames, so expect thousands of frames — within `maximumFrameCount` (100k) but worth confirming in Task 2's test with a realistic batch count. If exceeded, raise `maximumFrameCount` deliberately in a follow-up.
- **iPhone memory in `detail(for:)`**: mapping all samples into arrays for a long match is heavy. Acceptable for v1; note as follow-up (decimate to chart resolution).
- **arm64_32 trap rule**: any new integer conversions must use `UInt32(exactly:)` patterns per repo convention (see `FootySessionPackageV1.swift:333-342`).
- **Date task is a guard, not a fix** — if Step 2 of Task 4 fails, the plan pauses for diagnosis rather than papering over it.
