## 2. RISKS AND LIKELY BUGS FROM READING THE CODE

Ranked by immediate impact and strength of the source trace. P0 means data loss/crash; P1 broken feature; P2 misleading output.

1. **P0 — A late finish callback can seal the next recording.** After the 90-second watchdog fails, Retry permits a new session. An old HealthKit completion then takes the *current* writer/session ID, seals it with the previous session’s end date/metrics, and clears the new active state. No callback generation or builder-identity check protects this. **High confidence.** [WorkoutRecorder.swift:548](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/WorkoutRecorder.swift:548), [watchdog:812](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/WorkoutRecorder.swift:812)

2. **P0 — Concurrent R2 uploads can crash or remove the wrong pending item.** Startup, imports, and Settings Retry can overlap. `pushOne()` retains `pending.first` across `await`, then unconditionally calls `removeFirst()`. Two successful uploads of A can trap on an empty array or remove waiting B without uploading it. Swift actor isolation permits this reentry. **High confidence.** [SessionPushOutbox.swift:50](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Sync/SessionPushOutbox.swift:50), [callers:139](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Sync/PhoneWatchConnectivityCoordinator.swift:139)

3. **P0 — Finish can discard already-captured motion tail batches.** `stopAndDrain()` closes ingress without draining the separate delivery queue. Queued closures can subsequently submit to the finished buffer and be rejected after the failure result was read. Backlog drops are also omitted from this normal finish path. **High-confidence race; lost tail size depends on scheduling.** [MotionCaptureController.swift:512](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/MotionCaptureController.swift:512), [queued delivery:614](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/MotionCaptureController.swift:614)

4. **P0 risk — Opening a long session can exhaust iPhone memory.** Overview loading fully decodes every package frame, then copies all motion samples into additional arrays. Bounded list previews do not protect this detail path. A high-rate 90-minute package can therefore terminate report opening. **Allocations confirmed; device termination threshold unmeasured.** [FileSessionRepository.swift:405](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Storage/FileSessionRepository.swift:405), [motion copies:436](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Storage/FileSessionRepository.swift:436)

5. **P1 — Interrupted recovery can poison every later recovery attempt.** Recovery writes directly to a final `.footysession` filename. If the process dies mid-copy, the next attempt reuses that file based only on its name. Import rejects it, but the intact original partial is never rebuilt through that UI path. **High confidence.** [WatchSessionRepository.swift:191](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/Recording/WatchSessionRepository.swift:191), [WorkoutRecorder.swift:904](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/WorkoutRecorder.swift:904)

6. **P1 — Successful transport followed by failed import can wait forever.** A transient iPhone staging/import failure can produce no receipt. Watch moves to `waitingForReceipt`, which neither transfer claiming nor reconciliation retries; Recover Sessions skips the tracked digest. **High confidence.** [WatchTransferOutbox.swift:113](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/Sync/WatchTransferOutbox.swift:113), [iPhone failure:641](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Storage/FileSessionRepository.swift:641)

7. **P1 — Deleting an offline session blocks subsequent R2 backups.** Local deletion leaves its ID at the outbox head. Upload throws `sessionMissing`; `retryAll()` stops because the count did not change. Later valid sessions remain blocked across restarts. **High confidence.** [SessionPushOutbox.swift:57](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Sync/SessionPushOutbox.swift:57), [retryAll:102](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Sync/SessionPushOutbox.swift:102)

8. **P1 — Failed tombstone persistence can resurrect a deleted session.** A failed first Delete updates in-memory tombstones before writing disk. After freeing space, Retry sees that in-memory entry and skips persistence, then removes the package. Relaunch loses the tombstone; delayed duplicate delivery restores the session. **High confidence.** [FileSessionRepository.swift:504](/Users/prateekranka/Cowork/footballwatchos/Sources/iOS/Storage/FileSessionRepository.swift:504)

9. **P1 — Full-storage diagnostics can create an endless error loop.** Failed journal persistence logs an error; the logging mirror schedules another journal append, which fails and logs again. Persistent storage failure can consume CPU/battery during recording. **High confidence; eventual crash unproven.** [WatchDiagnosticJournal.swift:213](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/Diagnostics/WatchDiagnosticJournal.swift:213), [mirror installation:287](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/Diagnostics/WatchDiagnosticJournal.swift:287), [WatchLogging.swift:59](/Users/prateekranka/Cowork/footballwatchos/Sources/Watch/WatchLogging.swift:59)
